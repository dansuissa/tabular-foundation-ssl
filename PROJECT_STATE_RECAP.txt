================================================================================
1. WHAT THIS PROJECT IS
================================================================================

A lightweight research codebase for benchmarking semi-supervised learning (SSL)
methods on tabular classification datasets from OpenML.

Design principles:
- scikit-learn for data loading, preprocessing, classical models, and metrics
- PyTorch for neural SSL baselines (optional at import time)
- Absolute label budgets (not labeled fractions)
- One shared preprocessing pipeline for ALL methods
- Leakage-safe fitting: preprocessor never sees validation or test data
- CSV-based per-run logging with resume support
- Failure isolation: one crashing method does not stop the full benchmark

Out of scope for the current first wave:
- FT-Transformer, TabPFN, SAINT, GFTab, and other heavy transformer models

5. SPLIT AND PREPROCESSING PROTOCOL
================================================================================

--------------------------------------------------------------------------------
5.1 Default benchmark config (configs/benchmark.yaml)
--------------------------------------------------------------------------------

  seeds:                    [0, 1, 2, 3, 4]   (canonical wave uses 0,1,2)
  label_budgets:            [50, 100, 250, 500, 1000]
  test_size:                0.2
  val_size_from_labeled:    0.2
  use_all_remaining_as_unlabeled: true

  metrics:
    accuracy, balanced_accuracy, macro_f1, log_loss, roc_auc, average_precision


--------------------------------------------------------------------------------
5.2 Split protocol (src/splits.py)
--------------------------------------------------------------------------------

  1. Stratified train/test split (test_size=0.2, seed=seed)
  2. Sample exactly n_labeled examples from train pool with strict per-class rules:
       - n_labeled=50  → min 3 labels per class
       - n_labeled≥100 → min 5 labels per class
       - All classes must be present in labeled set
       - Remaining budget allocated proportionally (largest-remainder scheme)
  3. Split labeled set into labeled_train / validation (val_size_from_labeled=0.2)
       - Falls back to "no_val_low_label_multiclass" if stratified val split
         would leave too few labeled training examples per class
  4. All remaining train-pool rows become unlabeled train

  Failures:
    - InvalidBudgetError → status=skipped_invalid_budget
    - SplitError → status=failed


--------------------------------------------------------------------------------
5.3 Preprocessing (src/preprocessing.py) — SAME FOR ALL METHODS
--------------------------------------------------------------------------------

  Numeric columns:
    SimpleImputer(strategy="median") → StandardScaler()

  Categorical columns:
    SimpleImputer(strategy="constant", fill_value="missing")
    → OneHotEncoder(handle_unknown="ignore", sparse_output=False)

  Fit scope:
    preprocessor.fit(labeled_train + unlabeled_train) ONLY
    validation and test are transform-only

  No model-specific preprocessing exists.

--------------------------------------------------------------------------------

  label_propagation     sklearn LabelPropagation with robust retry ladder

  Robustness features:
    - Retries across neighbor counts [7, 15, 30, 50, 5, 3]
    - Caps graph at 20,000 rows
    - Validates outputs for NaN/inf
    - Raises GraphSSLNanError → status=failed_graph_ssl_nan
    - Raises GraphSSLMissingClassesError if labeled classes missing

--------------------------------------------------------------------------------

  threshold=0.90, max_iter=3, caps on pseudo-label volume per iteration

--------------------------------------------------------------------------------
8.7 Key conclusions from the canonical report
--------------------------------------------------------------------------------

  1. Gradient-boosted trees are the backbone. catboost and XGBoost/LightGBM
     family (supervised or self-trained) are most reliable across datasets.

  2. SSL benefit is real but narrow and small. Mainly self-training on large
     imbalanced binary datasets at ≥250 labels (bank-marketing flagship case).

  3. SSL tends to hurt on small multiclass data and at budget=50 labels.

  4. Neural SSL (vime/scarf/sslae) is not competitive on accuracy OR cost
     in this wave as currently configured.

  5. Graph SSL is bimodal: excellent on satimage, fragile on large binary data.

  6. self_training_lightgbm is the most frequent cell winner (9/40) and has
     the best mean SSL delta (+0.012).

  7. Dataset identity dominates method choice more than method family.

11. KNOWN GAPS AND LIMITATIONS
================================================================================

  README.md is PARTIALLY STALE:
    - Still describes some datasets as excluded from first wave (adult, etc.)
      but they are already in configs and benchmarked
    - Frames neural SSL as future work, but it is fully implemented

  No single end-to-end script for the full low-class wave exists; workflow is
  procedural across multiple scripts.

  vime_lite is implemented but intentionally excluded from canonical paper set.
  Do not report vime_lite results as "VIME".

  Graph SSL has known NaN instability at low budgets on large binary datasets.
  24 cells affected in canonical wave; handled with failure-aware ranking.

  Neural SSL may be under-tuned (fixed epoch/architecture budget, CPU defaults).
  Poor neural showing should be re-checked before treating as final negative.

  Only 3 seeds per cell in canonical wave — most rank differences inside the
  top pack are within noise.

  10 datasets, OpenML-only — regime coverage is thin (one hard multiclass
  jannis heavily shapes the "large" bucket).

  Single train/val/test protocol; results may shift under different validation
  strategies.

  Suggested next steps (from project's own reports):
    1. Fix graph-SSL NaN handling and re-run affected cells
    2. Focused deeper run on bank-marketing/adult (more seeds, more budgets)
    3. Sanity-check neural SSL training budgets before final negative claims
    4. Add more hard multiclass datasets to balance regime coverage
